# ES prop-portfolio pilot: spec (same as NQ SPEC except ...)

Read `../2026-09-29/SPEC.md` first (design, families, template, offline evaluator, Firms, desk-window rule). This pilot
repeats it on root ES. Everything below is the DIFFERENCE. Code is shared (parameterised, NQ defaults unchanged):
`PP_PILOT=es` (or `--pilot es`) makes the research scripts use root ES and this directory for data.

Root `RE = ~/ramos-quant-homebase/research/prop-portfolio/2026-09-30-es/` (data: queue.jsonl, jobs.jsonl, ledger.csv,
out/, bundles_cache/, progress.md, family_inputs.json). Code: `R = ../2026-09-29/` (template.py, families/, evalcore.py, ...).

## Instrument and costs
* Root ES (E-mini S&P 500): $50/point, tick 0.25 = $12.50. MES = ES/10: $5/point, tick $1.25.
* Tester runs at qty 1 ES, commission $4.00 RT per contract (tester default), slippage 1 tick/side (ES $12.50/tick).
* Offline resize to n MES: pnl = n x gross/10 - cost(n); cost(n) = floor(n/10) x $4.00 + (n mod 10) x $1.00 (ES mini leg
  $4.00 RT, MES $1.00 RT = Lucid sheet $0.50/side). Same function as NQ. Forced-flatten slippage = 2 ticks x $1.25 = $2.50
  per MES round trip (NQ: $1.00); day_stop / day_take fills use 1 tick x n x $1.25.
* Cost rule (RT cost < 3% of the stop's $ risk) uses ES numbers: 1 ES = $4 + 2 x $12.50 = $29 vs $50/pt x stop pts;
  1 MES = $1 + 2 x $1.25 = $3.50 vs $5/pt x stop pts. Stops are in POINTS and ES points are ~4x smaller than NQ points
  (ES ~ 4,500-6,000 vs NQ ~ 15,000-21,000): `stop_mode=pts` grids copied from NQ must be rescaled (ATR-mode defaults are unit-free).
* Contract caps unchanged in MICRO terms (Lucid 40 MES, Apex 100 MES; funded scaling 20/30/40). Fees: fees.json from R (assumptions).

## Drafts

`PP_PILOT=es gen_drafts.py` from the same template.py + families/ (21 drafts: 20 families + `random` control). All 21 load via
`/api/tester/strategies`; `PP_PILOT=es localcheck.py` passes on the synthetic tape. NQ drafts regenerate byte-identically.

## Driver (one daemon, one queue) and caps
* `hb.py` (R) is still the ONLY submitter; ONE daemon serves both pilots: <= the machine slot cap of our jobs at once across NQ+ES (`homebase.backtest.slots.cap_at`: 2 in desk hours 08:00-16:15 ET weekdays, 4 otherwise), queued jobs taken
  NQ first (each pilot in its own queue order), so ES never reorders NQ jobs. Job field `"pilot": "nq"|"es"` (default nq); `hb.py submit`
  routes each line to that pilot's queue.jsonl (an NQ draft in an ES job, or v.v., is refused). Ledger rows go to `RE/ledger.csv`,
  job state to `RE/jobs.jsonl`, the auto block to `RE/progress.md`.
* Caps are counted PER pilot: 400 screening runs (stages screen|ctrl), 3,000 heat-map cells, 15 walk-forwards (ES has its own full budget).
* Stages/names as NQ: `calib` (smoke, calibration), `screen` (20 families x tf {1,5,15,30}, sess all, defaults, qty 1), `ctrl`
  (random ctrl p_entry 0.1 seeds 1-3 + randomtod seed 1; ctrl2 p_entry 0.5 seeds 11-13 + randomtod seeds 11-12; all 4 tf = 36 runs).
  Job lines come from `queue_gen.py` (smoke | calib | screen | ctrl).
